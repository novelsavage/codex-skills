# AI Slop を避ける

## 原則

「よくあるAI生成UI」に見える原因は、個々の技法ではなく、文脈なしに既定技法を束で適用することにある。禁止リストを別のテンプレへ変えず、各判断を画面の仕事へ接続する。

## 既定で採用しない表現

- 紫〜青の大面積グラデーション
- 見出し文字のグラデーション塗り
- 意味のない発光、ぼかし球、背景ブロブ
- 題材と無関係な黒地＋蛍光緑
- 大きな角丸、薄い影、白背景を組み合わせたカードの反復
- 同じ大きさの3カードを並べるだけの特徴紹介
- ラベル、ボタン、状態表示をすべてピル形状にする
- 読みにくさだけを増やすガラス表現
- ライブラリ既定値のままのコンポーネント集合
- 小ラベル、巨大見出し、抽象説明、2つのCTAという定型ヒーロー
- 根拠のないKPI、受賞、顧客ロゴ、推薦文
- 全要素のスクロール連動フェードイン
- 製品固有の情報を持たない詩的コピー
- 実サービスらしく見せるためだけの架空データや架空ブランド

## 例外を認める条件

| 表現 | 妥当になり得る条件 |
|---|---|
| グラデーション | 地図の高度、音量、時間、密度など連続量を符号化する |
| 大きな角丸 | カメラのシャッター、アバター、明確なタッチ対象を表す |
| 影 | モーダル、ドラッグ対象、フォーカス、紙の重なりを示す |
| カード | 独立対象、自己完結したフォームや要約、開閉可能な詳細など、境界が理解を助ける |
| ガラス表現 | 地図や映像の上に情報を重ね、背景文脈を保つ必要がある |
| 暗色＋蛍光色 | 夜間地図、ターミナル、音響監視など用途と環境が一致する |
| 表示書体 | 短いロゴ、見出し、識別子に限定される |

例外を使う際は、「なぜこの題材・操作に必要か」を一文で説明できること。

## コピー規範

抽象語を、対象・操作・結果へ置き換える。

| 避ける | 書き換え例 |
|---|---|
| 記憶の可能性を解き放つ | 写真と場所を地図に記録する |
| あなたの体験を再定義 | OCR結果を確認してノートへ追加 |
| シームレスにつながる | 選択したノードの関係を右側に表示 |
| 次世代のワークフロー | 未確認の画像を上から順に処理 |
| Get Started | 地図を作成 / 画像を読み込む |

説明文がなくても操作できるなら削る。必要なら、入力条件、処理時間、保存先、失敗時の対処を書く。

## レイアウト監査

次を確認する。

1. 主役がカード群より強く見えるか。
2. 同じ丸み・影・余白が惰性で繰り返されていないか。
3. 境界線や余白だけで成立する区切りをカード化していないか。
4. すべての要素が中央揃えになっていないか。
5. 情報量の違いが、サイズ・位置・密度に反映されているか。
6. テンプレを外しても題材が判別できる語彙と操作があるか。

## コンポーネント監査

- ボタンに主・副・危険の序列がある
- チップとボタンが見分けられる
- アイコンだけの操作に名前がある
- 表は比較可能なままで、各行が巨大カードになっていない
- グラフは装飾ではなく、問いに答える軸・凡例・選択を持つ
- 空状態がマーケティングコピーではなく次の操作を示す
- エラーが原因と回復方法を示す

## 外部の反AI-slop資料を使うとき

公開チェックリストや記事は、問題の語彙化と見落とし防止に使う。流行ごと禁止事項を増やすのではなく、次の三分類へ整理する。

- 文脈欠如: 題材と無関係な見た目
- 構造欠如: 主役や操作順がなくカードで分割しただけ
- 信頼欠如: 架空データ、抽象コピー、説明不能な装飾

外部資料とこのスキルが衝突した場合、現在のユーザー指示と実際の利用状況を優先する。
