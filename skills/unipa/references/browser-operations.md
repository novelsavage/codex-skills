# UNIPAのブラウザー操作

広範囲の調査、初めて見る画面、ブラウザーの復旧時に参照する。

## 操作と確認の流れ

クリック、入力、選択、キー操作のたびに次を行う。

1. 新しいDOMスナップショットで現在の画面を見る。重なり、アイコン、ダイアログがDOMから分からない場合だけ、代わりにスクリーンショットを使う。
2. 表示中の見出しと画面コード、対象科目、選択中の区分・タブ、開いているダイアログ、URLの手掛かりを把握する。
3. 操作対象は直近のスナップショットから特定する。安定した属性、対象範囲に絞った役割とアクセシブル名、絞った表示テキストの順に優先する。
4. 対象が表示中の1要素に特定できることを確かめる。同じ表示名があるときに、単に何番目かで選ばない。
5. 一つの操作を行う。
6. 見出し、選択タブ、ダイアログ名、状態表示、ファイル名、完了メッセージ、URLなど、最小限の確かな変化を確認する。
7. DOMが変わった、または操作が失敗した場合は、次の対象を特定する前にスナップショットを更新する。

タイムアウトや対象の曖昧さが出たら、同じ指定で機械的に再試行しない。画面を見直し、重なったダイアログを閉じるか、対象範囲を絞るか、新しいスナップショットにある安定した属性へ切り替える。

## 読み取り専用の調査

広範囲の調査を依頼された場合は、次のように進める。

1. フッターの`サイトマップ`で、個々の項目を開く前に上位機能を一覧にする。[portal-map.md](portal-map.md)も読む。
2. 操作候補を分類する。
   - 安全に読めるもの：時間割、科目一覧、資料・課題の一覧、シラバス詳細
   - 閲覧記録が残り得るもの：掲示やメッセージの詳細、アンケート、出欠・成績の詳細
   - 状態を変えるもの：許可を伴うダウンロード、WebNoteへのコピー、お気に入り、アップロード、保存、提出、登録、予約、回答、ログアウト
3. 安全に読める場所を、ポータルトップ、掲示一覧、時間割、クラスプロファイル、課題、資料、シラバス、その他の依頼箇所の順に確認する。
4. 閲覧記録が残り得る場所に入る前に、`未読`・`既読`、確認ボタン、承認操作の有無を表示から調べる。その影響が依頼の範囲に入らなければ開かない。
5. 各場所では見出し、画面コード、必要な件数・状態・日付、到達経路だけを記録する。
6. 多数の科目で同じ構造が続く場合は、構造が分かる範囲で確認を止め、残りの範囲を報告する。
7. 確認済み、安全上省略、認証・セッション・UIで進めず、未確定の範囲をまとめる。

対象はユーザーに表示される画面であり、隠れたエンドポイントの探索ではない。URLの推測、生成IDの列挙、保存領域の調査、隠しフォーム値の収集はしない。

## UNIPA特有の対象指定

- 同じ表示名が繰り返されるときは、利用中の科目パネル、表の行、カード、ダイアログ、選択中のタブに絞る。
- `j_idt...`などのJSF IDは、そのスナップショット限りのものとして扱う。画面遷移や一部更新後に使い回さない。
- 表示中の日本語ラベルと、現在のスナップショットにある安定した`href`を優先する。見えているURLから別のURLを組み立てない。
- AJAXによる遷移ではURLと本文が食い違うことがあるため、URLは手掛かりにとどめる。
- アドレスバーより、`学生時間割表[Kmd008]`、`課題提出[Jga005]`、`授業資料[Jga023]`のような見出しと画面コードを優先する。機能が切り替わっても前のURLが残ることがある。
- ダイアログが開いているときは、そのダイアログ内の`閉じる`を特定する。文字のない閉じるボタンは、現在のスナップショットにあるクラス名や要素IDで特定する場合がある。

## 観察する範囲

- `学生時間割表`では、単位修得状況などの学修進捗を依頼された場合を除き、ページ全体のDOMスナップショットを取らない。時間割の下に画面外のGPAや単位の表がある。
- 課題一覧は依頼された行と必要な列だけを読む。提出者名、提出時刻、点数、講評、他の提出者の情報が表に含まれることがある。
- シラバス検索では、所属やカリキュラムの選択肢にある全`<option>`を出力しない。表示範囲のスクリーンショットか、選択中の値と項目名だけを見る。
- DOMスナップショットが`<option>`の繰り返しばかりで画面構造が分からない場合は、表示範囲のスクリーンショットに切り替え、特定した部分だけをDOMで読む。

## 復旧とタブの扱い

- クリックが反応しなければ、`ファイル一覧`、警告ダイアログ、無効なボタン、古いスナップショット、一部だけのAJAX更新を調べてから再試行する。
- DOMの確認が一度タイムアウトした場合は、ブラウザー操作ツールのトラブルシューティングを参照し、画面が反応するか確認してから、対象を絞った観察を一度だけ再試行する。繰り返し続けない。
- 既存のUNIPAタブを別のCodexブラウザーセッションが使っている場合、ログイン済みタブを重複して開かない。以前のタスクの終了・解放か、正常なタブの開き直しをユーザーに頼む。
- 終了時は、タブの利用状態を確定する操作を最後に一度だけ行う。ログインや確認待ちなど作業が残る画面は`handoff`にし、それ以外は確保したタブを解放する。
