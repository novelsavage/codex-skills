# 作業手順

## 画面を開いて状況を把握する

1. 既に開いているUNIPAタブを優先して使う。
2. 開いているタブがなければ、ユーザーが指定したブックマークまたは既知のポータルURLを開く。
3. ログイン画面が出た場合は、保存済みの入力欄が埋まっているときだけ送信する。送信するのは、ユーザーがログインを依頼している場合に限る。
4. Chrome が Windows Hello の確認を求めた場合は、ユーザーに PIN や生体認証を完了してもらう。Codex は保存パスワードの中身を読まない。
5. パスワード欄が消え、ポータルメニューが表示されたことを確認する。
6. 画面の状態は、URLやページタイトルだけで判断しない。UNIPAでは、URLがクラスプロファイル系のままでも、本文がポータルトップ相当になることがある。

主な入口は次のとおり。

- おしらせ
- 時間割
- シラバス
- 履修登録&抽選申請
- 学生カルテ
- アンケート
- 申請&予約
- クラスプロファイル

## 授業資料を確認する

1. 今日の時間割、授業名、またはクラスプロファイルから対象授業を特定する。
2. 対象授業の `クラスプロファイル` を開く。
3. クラスプロファイルでは [class-profile.md](class-profile.md) を読む。`授業資料 Class material` の中央カードまたは一覧リンクを優先する。
4. `授業資料一覧` では、`第9回 授業資料` のような行タイトルを開く。`コピー` は押さない。
5. 詳細画面では、`授業実施日`、`授業資料公開期間`、`資料内容` を確認する。
6. `添付資料を確認` を押すと `ファイル一覧` が表示される。これで、ダウンロードせずにファイル名を確認できる。
7. ユーザーがダウンロードを依頼した場合だけ、実際のファイルリンクを押す。ダウンロード後は、ファイル名、取得元、保存先を報告する。
8. 似た名前の資料が複数ある場合は、どれを取得するか確認する。

## 課題を確認する

1. 時間割、クラスプロファイル、または課題提出画面から対象課題を探す。
2. `課題`、`レポート`、`提出`、`期限`、`未提出`、`提出済` などのラベルを手掛かりにする。
3. 次の情報だけを抽出する。
   - 授業名
   - 課題名
   - 提出期限
   - 提出状態
   - 指定形式
   - 課題内容の要点
   - 添付ファイル名
4. 説明が長い場合は要約する。正確な条件が必要なときだけ、該当箇所を短く引用する。
5. 詳細画面の `添付資料を確認` で `ファイル一覧` を表示できる場合がある。テンプレートや参考資料の確認に使う。
6. `確定`、`一時保存`、`提出` は押さない。

## 課題提出の準備をする

1. 先に [safety.md](safety.md) を読む。
2. 授業名と課題名が、ユーザーの依頼と一致していることを確認する。
3. アップロードするローカルファイルが存在することを確認する。
4. 画面のファイル選択欄にファイルを指定する。
5. `提出`、`登録`、`確定`、`送信`、最終確認の `OK` の直前で止める。
6. ユーザーに、授業名、課題名、ファイル名、押すボタンを示して確認する。
7. ユーザーが承認した場合だけ送信する。
8. 送信後は、完了メッセージ、`提出済` 表示、提出状態の変化で結果を確認する。

## 掲示と時間割を確認する

- 掲示は、一覧のタイトル、日付、発信元を確認してから詳細を開く。
- 掲示本文は要約し、必要な行動がある場合だけ明示する。
- 時間割は、UNIPA内の日付操作を使う。ブラウザの戻るボタンを使わない。
- 時間割を報告するときは、日付、時限、授業名、担当教員、教室、クラスプロファイルやシラバスへの導線をまとめる。

## うまく動かないとき

- 遷移直後に画面が空白になったら、少し待ってから本文とメニューを確認する。
- クリックしても変化がない場合は、最新の画面状態を取り直す。ダイアログ、モーダル、スクロール位置、隠しフレームの有無を見る。
- クラスプロファイル上部のボタンが動かない場合は、開いているダイアログを閉じ、中央カードまたは左側の授業一覧を使う。
- `サーバーとの通信中にエラーが発生しました` と表示されても、目的の内容が見えている場合がある。その場合は警告として記録し、同じ操作を繰り返さない。
- セッションが切れた場合は、ユーザーに再ログインを依頼する。
- 複数セッションに関する警告が出た場合は、どのタブを残すかユーザーに確認する。
