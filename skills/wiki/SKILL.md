# Wiki

`~/Projects/llm-wiki`を、ユーザーが直接操作する百科事典ではなく、複数のAIエージェントが共通参照し複利的に育てる長期記憶（Semantic / Evergreen 知識ベース）として扱う。

## 前提

- `~/Projects/llm-wiki/AGENTS.md`と`~/Projects/llm-wiki/wiki/index.md`が存在することを確認する。どちらかが見つからない場合は、Wikiや不足ファイルを推測で新規作成せず、不足しているパスと準備が必要なことをユーザーへ伝えて停止する。
- 書き込みを伴う作業の前に`git -C ~/Projects/llm-wiki status --short`を確認する。リモートがあり通信できる環境では`git -C ~/Projects/llm-wiki fetch origin`で`origin/main`との差分も確認する。作業ツリーがクリーンで単純なfast-forwardが可能なら最新化してよい。未コミット変更とリモートの先行が重なる、または競合の恐れがある場合は上書きせずユーザーへ確認して停止する。

## 毎回の流れ

1. `~/Projects/llm-wiki/AGENTS.md`を読み、ディレクトリ構成、Frontmatter、統制タグ、リンク、プライバシー境界などの最新規約を唯一の正として従う。
2. 索引をコンテキストへ取り込む。すでにセッション開始フック等で索引がコンテキストへ注入済みなら再読込しない。未注入なら`python3 ~/Projects/llm-wiki/scripts/session-inject.py --raw`（スクリプトが無い環境では`~/Projects/llm-wiki/wiki/index.md`）を読む。
3. 現在の依頼に関係するページ（必要なら関連MOCや`playbooks/`・`comparisons/`を含む）だけを読み、一次根拠が必要な場合だけ`sources/`や`raw/`を確認する。
4. Wikiの情報を回答、判断、執筆、実装へ自然に反映する。日常的な参照をユーザー操作として要求しない。
5. 作業中に恒久的な新情報・決定・訂正・再利用可能な手順や比較判断が確定したら、下記の基準でWikiを更新する。
6. 更新した場合は関連ページ・MOC・`wiki/index.md`・`log.md`の整合を同じ作業内で整え、`python3 ~/Projects/llm-wiki/scripts/wiki-lint.py`（存在すれば）を実行して**0エラー**を確認する。

## 読む

- 本人の背景、制約、過去の決定、好みが成果へ影響しうる場合は、明示指示を待たずに読む。
- `status`（`active` / `evergreen` / `completed` / `parked` / `hypothesis` 等）と`confidence`を考慮し、`low`や`hypothesis`・`parked`を確定した現在事実のように断定しない。
- Wikiと現在確認できる一次情報が矛盾する場合は一次情報を優先し、矛盾を明示する。
- 通常の背景参照だけではWikiを書き換えず、`log.md`の`QUERY`も増やさない。

## 自動で記憶する

次の条件をすべて満たす知見は、個別の承認を待たずに最小限だけ取り込む。昇格すべき恒久知識が無い場合は何も書かず終了する（No-opを正常とする）。

- ユーザーが明言した、成果物やコマンド結果で確認した、または信頼できる一次情報で検証した
- 一時的な予定・作業メモではなく、将来の会話や作業でも再利用できる
- `AGENTS.md`のディレクトリ型（`profile/`・`projects/`・`people/`・`works/`・`concepts/`・`playbooks/`・`comparisons/`・`sources/`等）に照らして更新先または配置先が明確である
- 秘密情報、PII、第三者のセンシティブな私事を含まない

対象例は、本人の確定事実・訂正、完成または節目を迎えたプロジェクトや実績、継続的な好み、確定した設計判断、再利用可能な環境構築・トラブル解決手順（`playbooks/`）、複数選択肢の比較判断（`comparisons/`）とする。単発のエラー途中経過、作業中だけの仮パス、単発の予定・天気・返信下書き、未確定の伝聞やモデルの推測は保存しない。

## 確認してから記憶する

次の場合は候補と理由を短く提示し、ユーザーの承認後に書き込む。

- 本人についての推定、解釈、`confidence`が`low`になる情報
- 健康、家族、金銭、私的な連絡など、保存判断が機微な情報
- 第三者の私生活や評価に関わる情報
- 大量取り込み、`raw/`への新規保存、既存ページの削除・リネーム、既存構造や`AGENTS.md`・`scripts/`の大幅変更
- 既存の典拠と解消できない矛盾がある情報

パスワード、トークン、APIキー、秘密鍵、電話番号、詳細住所、学籍番号などの機微情報は、承認の有無にかかわらず保存しない。

## 更新と保守

- **Extend, don't create**: まず既存ページの更新・深化で解決できないか検討し、会話ごとのページ乱立や水増しリンクを作らない。
- **鮮度維持と断片保全**: 時事的な現在地ページや進行中案件は時系列の追記で肥大化させず最新状態へ上書き整理し、完了・保留になった案件は`status`を更新する。独立ページにするには小さい着想は捨てず、`AGENTS.md`に定める断片集ページへ日付・出典付きで集約する。
- **出典とハイブリッド引用**: `sources/`に出典ノートを揃える（小規模・日次の対話更新では既存または月次ロールアップ出典へ集約し、出典ファイルの乱立を防ぐ）。本文末尾の典拠ブロックには出典・日付・対象識別子に加え、本人の短い核心発言のみを添え、AI側の長い一般論は引用しない。
- **規約準拠と機械CI**: `AGENTS.md`のFrontmatter（`status`含む）、統制タグ語彙、デュアルリンク（Obsidian側ターゲットは実ファイル名と完全一致）、MOC、`wiki/index.md`、`log.md`形式を厳守する。編集後は`python3 ~/Projects/llm-wiki/scripts/wiki-lint.py`で**0エラー**を確認する（スクリプトが無い場合は変更周辺を手動点検する）。
- **Git運用**: `raw/`の削除、大量改名、履歴の書き換えは事前確認する。コミットとpushは原則として明示指示があるときだけ行う（`AGENTS.md`に定期自動整備の例外規約がある定期タスクを除く）。コミットメッセージに`Co-Authored-By`トレーラーは付けない。

日常的な読み取りは最終回答で報告しなくてよい。Wikiへ実質的な変更を加えた場合だけ、保存した要点、変更先、`wiki-lint.py`の結果を簡潔に伝える。
